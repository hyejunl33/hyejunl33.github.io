# PRD — Hyejunl33 Interactive Blog Demo

## 1. 문서 목적

기존 블로그의 글·분류·CV를 바꾸지 않은 상태에서, 새 UI 방향을 판단할 수 있는 **홈 화면 인터랙션 데모**를 만든다. 이 문서는 운영 사이트 전환 명세가 아니라, 디자인/기술 방향을 확정하기 위한 데모의 범위와 성공 조건을 정의한다.

## 2. 결정된 디자인 방향

### 한 줄 콘셉트

**“차분한 연구 아카이브 위에, 커서에 반응하는 하나의 궤도와 빛을 둔 포트폴리오.”**

기존 시안의 A(Orbital archive)와 D(Holo index)를 섞는다.

- A에서 가져올 것: 포인터에 미세하게 반응하는 원형 궤도, 깊이감, 느리고 부드러운 움직임
- D에서 가져올 것: 카드 표면에만 쓰이는 빛 반사와 오로라형 그라데이션
- OpenAI 웹사이트에서 참고할 것: 넓은 여백, 명확한 정보 위계, 절제된 탐색 구조와 콘텐츠 중심의 카드 구성. 현재 홈페이지도 탐색 메뉴와 최신 콘텐츠를 분명한 섹션으로 나눈다. [OpenAI 홈페이지](https://openai.com/)
- 의도적으로 제외할 것: 화면 전체 WebGL, 과한 패럴랙스, 상시 움직이는 글리터, 커스텀 커서, 콘텐츠를 가리는 효과

참고한 Pokémon Cards CSS 홀로그램 구현은 CSS 3D transform·gradient·blend mode와 포인터 위치를 이용해 표면 효과를 만든다. 이 데모에서는 그 방식을 **대표 프로젝트 카드 1개**에만 절제해 사용한다. [Pokémon Cards CSS Holographic Effect](https://poke-holo.simey.me/)

## 3. 문제와 목표

### 해결할 문제

현 블로그는 콘텐츠는 충실하지만, 첫 화면에서 작성자의 AI 학습/프로젝트 정체성과 포트폴리오 가치를 빠르게 전달하지 못한다. 일반적인 테마 포크처럼 보이지 않으면서도 글 읽기 경험을 희생하지 않는 UI 언어가 필요하다.

### 데모 목표

1. 첫 10초 안에 “AI 연구·학습 아카이브 + 프로젝트 포트폴리오”임을 전달한다.
2. 상호작용은 홈페이지의 감정적 인상만 높이고, 탐색과 읽기를 방해하지 않는다.
3. 모바일·저사양·reduced motion 환경에서도 같은 정보 구조가 완전히 동작함을 보인다.
4. 이후 실제 빌드에서 Jekyll 글/분류/CV를 그대로 연결할 수 있는 컴포넌트 경계를 제안한다.

### 데모 비목표

- Jekyll/Astro 마이그레이션 실행
- 기존 Markdown, frontmatter, URL, CV JSON 수정
- 게시글 전문·검색·댓글·분석 도구의 완성 구현
- 실시간 3D 엔진, 모델 파일(GLB), 외부 API 추가

## 5. 데모 정보 구조

데모는 하나의 반응형 홈 화면으로 만든다. 링크는 데모 단계에서는 앵커/더미 경로여도 되지만, 라벨과 데이터 모델은 운영 구조를 따른다.

1. **고정 헤더** — `Journal`, `Projects`, `CV`, `About`, 테마 토글
2. **Hero** — 이름, 한 문장 소개, CTA 2개, 인터랙티브 궤도 오브젝트
3. **Featured project** — 홀로그램 반사 카드 1개와 프로젝트 요약
4. **Recent notes** — Algorithm / Project / Study log의 실제 분류 체계를 반영한 3개 카드
5. **Archive strip** — 연도·카테고리로 이어지는 조용한 탐색 영역
6. **Footer** — GitHub, 이메일, RSS/저작권 영역

## 6. 인터랙션 명세

### 6.1 Orbital field (A의 핵심)

- Hero 우측/배경에 하나의 중심 원과 2~3개의 가는 궤도를 둔다.
- 포인터가 Hero 안에서 움직이면 중심 원은 포인터 반대 방향으로 최대 8px 이동하고, 궤도는 최대 4도 기울어진다.
- hover하지 않을 때는 12~16초 주기의 매우 느린 부유 움직임만 사용한다.
- 클릭 가능한 콘텐츠가 아닌 장식이다. keyboard focus나 스크린리더에 노출하지 않는다.
- 모바일에서는 포인터 반응을 끄고, 정적인 그라데이션 원으로 대체한다.

### 6.2 Aurora project card (D의 핵심)

- Featured project 카드만 CSS `transform`, `linear/radial-gradient`, `mix-blend-mode`로 구성한다.
- 포인터 위치가 카드의 빛 반사 위치와 최대 `rotateX/Y ±5deg`만 바꾼다.
- 카드의 제목/태그/링크는 항상 대비를 확보한 별도 콘텐츠 레이어에 둔다.
- 카드 밖으로 포인터가 나가면 180~240ms 안에 중립 상태로 복귀한다.
- `prefers-reduced-motion: reduce`에서는 기울기와 애니메이션을 모두 제거하고 정적 오로라 배경만 남긴다.

### 6.3 콘텐츠 모션

- 섹션은 한 번만 12~20px 위로 올라오며 나타난다.
- 스크롤 기반 고정(pin), 가로 스크롤, 무한 루프 모션은 사용하지 않는다.
- 클릭/hover 상태는 150~250ms 범위의 opacity/transform만 사용한다.

## 7. 시각 시스템

### 색

- 기본 표면: 거의 흰색 또는 따뜻한 중성색, 본문은 높은 대비의 차콜
- 어두운 모드: 검푸른 흑색 표면, 과도한 네온은 피한다.
- 포인트: 보라 → 청록 → 복숭아색의 저채도 aurora gradient
- 그라데이션은 Hero의 빛, featured 카드, 섹션 구분선에 한정한다.

### 타이포그래피와 레이아웃

- Hero 제목: 큼직하고 짧은 2~3줄, 지나친 display font는 사용하지 않는다.
- 글 카드: 제목·분류·날짜의 3단 위계만 사용한다.
- 데스크톱 콘텐츠 폭: 1,120~1,240px, 본문 읽기 폭은 별도 680~760px로 제한한다.
- 카드 모서리·그림자는 부드럽되 glassmorphism을 모든 요소에 반복하지 않는다.

### 본문 UI 기준

- SEED의 composition·responsive design·interaction states 원칙처럼, 반복되는 본문 요소는 일관된 간격·색상·상태를 가진 독립된 단위로 설계한다. [SEED React](https://seed-design.io/react)
- Toss 앱의 화면/내비게이션 문서가 강조하는 화면 단위 정보 위계와 예측 가능한 이동 구조를 적용한다. 목록 → 글 상세 → 같은 분류 목록으로 돌아가는 흐름을 항상 제공한다. [Toss React Native 문서](https://developers-apps-in-toss.toss.im/documentation/react-native)
- 코드 블록은 언어 라벨, 구문 색상, 충분한 대비와 여백을 제공한다. 기본 언어는 Python으로 본다.
- 표는 헤더와 본문을 분리하고, 작은 화면에서 가로 스크롤 컨테이너 안에 넣어 본문 폭을 깨지 않는다.
- 글 상세에는 breadcrumb, 제목/요약/날짜, sticky 목차, 읽기 진행 표시를 기본 구성으로 둔다.

## 8. 기술 제약과 성능 예산

| 항목 | 데모 기준 |
| --- | --- |
| 인터랙션 방식 | CSS custom property + 포인터 이벤트 + 필요 시 작은 Canvas. Three.js/R3F는 사용하지 않는다. |
| JavaScript | Hero/featured 카드 인터랙션만. 글 목록은 JavaScript 없이 보인다. |
| 이미지 | 외부 대형 배경 이미지/3D 모델 없이 CSS로 구현한다. |
| 모션 접근성 | `prefers-reduced-motion` 완전 지원, 모든 핵심 정보는 모션 없이 노출 |
| 모바일 | 375px부터 가로 스크롤 없음, 궤도/카드는 정적 fallback 제공 |
| 성능 목표 | 초기 표시용 JS 35KB gzip 이하, 60fps 목표, Lighthouse Performance 90+ (데스크톱) |

## 9. 기존 블로그와의 연결 계약 (후속 구현용)

데모는 데이터 파일을 바꾸지 않는다. 실제 구현 때 아래 계약을 유지한다.

| 기존 원본 | 새 UI에서의 역할 | 보존 조건 |
| --- | --- | --- |
| `_algorithm/*.md` | Algorithm 글 목록/상세 | 파일·frontmatter·현재 URL 보존 |
| `_projects/*.md` | 프로젝트 및 featured project | 파일·frontmatter·현재 URL 보존 |
| `_etc/*.md` | Study log/essay | 파일·frontmatter·현재 URL 보존 |
| `_data/cv.json` | CV 타임라인/다운로드 링크 | JSON 원본 보존 |
| `_data/navigation.yml` | 주 메뉴 출발점 | 라벨과 링크를 우선 재사용 |

## 10. 데모 산출물

1. 독립 실행 가능한 단일 홈 화면 데모
2. 다크/라이트 또는 고대비 중 최소 한 가지 테마 전환 상태
3. 포인터 가능 환경과 reduced motion 상태를 확인할 수 있는 제어/미디어 쿼리
4. 실제 블로그 콘텐츠를 수정하지 않는 시드 데이터
5. 이 PRD에 대한 구현 메모: 사용한 CSS 속성, fallback, 추후 콘텐츠 연결 지점

## 11. 수용 기준

- [ ] A의 orbital interaction과 D의 aurora 카드가 하나의 디자인 언어로 보인다.
- [ ] 화면 전체가 홀로그램/3D 효과로 채워지지 않는다.
- [ ] Hero에서 Journal, Projects, CV가 명확히 발견된다.
- [ ] 포인터를 움직이지 않아도 모든 텍스트와 CTA를 읽고 사용할 수 있다.
- [ ] 375px, 768px, 1440px 레이아웃에서 겹침/가로 스크롤이 없다.
- [ ] reduced motion에서 자동 움직임·3D tilt가 없다.
- [ ] 기존 Markdown/CV 파일에는 변경이 없다.
